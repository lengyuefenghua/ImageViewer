## Workflow
- 任何开发请求先通过 skill 工具加载 `using-lazy-flow` 分级，再行动；已注册技能不需要通过文件搜索寻找。
- 使用 Lazy Flow 分级：`tiny` 最小修改（文案/样式/小修复/局部优化，可跨文件不改契约；重要代码必须聚焦测试；不审查；三行记录到 `docs/changes/tiny-log.md`）；`patch` 单功能/子系统行为变更（垂直切片跨层不算跨模块）+ 轻量审查；`full` 仅限共享契约/架构级重组/数据迁移/高不确定性 + 双轴审查。
- 行为变更优先 TDD，除非任务明确是 tiny。
- full 变更澄清先统一核心术语（写入 `CONTEXT.md`），需求确认结论落盘到 `docs/changes/<change>/proposal.md` 的需求确认段，再进入设计。
- full 实现默认 inline；任务可并行或需隔离上下文时按 `subagent-dev` 派发子代理，主控负责验证、审查和收尾。
- full 变更不自动续跑：完成前逐条核对 `tasks.md` 是否完整实现（不是最小实现/偷懒），未完成继续、全部完成才收尾。
- `/goal <最终目标>` 启动的 active Lazy Goal 对已确认范围提供一次性实施授权；每个可验证步骤记录进展，只有最终目标满足后才能完成 Goal。
- full/patch 变更完成前必须自审（收尾门统一执行，逐条对照 specs/tasks，确认完整实现、无遗漏）；提交是 `tasks.md` 里的任务点：归档后执行 `git commit`（仅该变更相关文件、中文提交说明、只 commit 不 push）。
- 界面/前端/GUI 变更：澄清阶段给文字 UI 草图（`design.md` 的 `## UI 草图`；patch 放对话），并问用户是否使用视觉测试与验证（`visualVerify`），复杂界面再问是否产出 HTML 设计效果 demo（`designDemo`）；`visualVerify=false` 时本变更不得使用 `opencode_computer_*`；`designDemo=true` 时产出单文件 `design-demo.html`（内联 CSS/JS、示例数据、基本交互，无框架/无构建）；`visualVerify=true` 时用自动化操作工具做闭环视觉实际验证。
- 声明 done/fixed/passing/complete/ready 之前，在当前回合运行相关验证命令并读取输出。
- 完成声明与推送前只跑 tasks.md 列出的最小相关命令，禁止惯性全量。
- 只有存在真实且长期值得记录的取舍时才写 `docs/adr/` 决策记录。

## 代码注释
- 注释用中文。
- 默认不写；但关键处**必须**有注释：非显然的为什么/权衡、不变量、边界条件、平台或库怪癖、反直觉分支、公共 API 契约。关键处缺失注释视为缺陷。
- 只写意图、约束、边界或为什么（如平台限制、反直觉处理、安全考量），不复述代码。
- 禁止执行过程叙述（“先…再…”“这里我们…”）、复述代码、变更史。
- 名字能表达的、平凡代码（getter、显然的赋值/循环）不加注释。

## 日志
- **日志是行为变更的交付物**：所有行为变更必须评估并列出日志点（事件 + 级别 + 上下文）；涉及外部边界 / 异常降级重试 / 状态转换 / 用户可见结果的必须落地，确实不适用的写明原因。用级别控制输出内容；缺日志视为未完成。
- **豁免**：很小的一次性验证/临时项目（spike、一次性脚本、临时 demo）按项目整体豁免，需一句话说明。
- 优先使用仓库已有的 logger；不要为此引入新依赖。
- 日志文案跟随仓库惯例（通常英文）。
- 级别从低到高：
  - TRACE：最细粒度跟踪（框架内部流程、逐行调试），生产一般关闭。
  - DEBUG：调试信息（变量值、分支走向），开发/排障时使用。
  - INFO：正常运行信息（启动、配置加载、关键业务节点）。
  - WARN：警告（潜在问题、重试、降级、容量接近阈值）。
  - ERROR：错误（当前操作失败，通常需要关注或告警）。
  - FATAL：致命错误（服务/进程无法继续运行）。
- 必须记录的点：外部边界（I/O、网络、DB、文件、子进程）的调用与失败；异常/降级/重试/回退路径及原因；关键状态转换（开始/结束、状态机迁移）；启动与关闭。
- 每条日志带定位上下文（实体/请求/任务标识 + 动作 + 结果）。
- 禁止：密钥/token/密码/PII 等敏感数据；循环内逐条刷屏；无信息占位日志；把日志当注释复述代码。

## 文档层级
- 每个事实只有一个家：决策 → `docs/adr/`；行为契约 → `docs/specs/`；术语 → `CONTEXT.md`；需求确认 → `docs/changes/<change>/proposal.md` 的需求确认段；变更过程 → `docs/changes/`；tiny 记录 → `docs/changes/tiny-log.md`；常设规则 → 本文件。
- 别处引用用相对路径链接，不粘贴副本。
- 写当前状态，不写变更史（"之前/现在"这类叙事只允许在 ADR 和归档中）。

## Gotchas
- 只保留仓库特有的陷阱、前置条件、昂贵测试套件、环境怪癖，或 agent 很可能忽略的约定。
